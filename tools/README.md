# 제작·분석 도구

`work_ogg`에는 기존 작업의 Python 소스를 보존했습니다. `work_ogs`의 두 모듈은 해당 도구가 사용하는 공통 코덱·R5900 실행 검사기입니다. 별도 OGs 프로젝트의 게임이나 작업 결과는 포함하지 않습니다.

Python 3.11에서 작성했습니다. 외부 라이브러리는 `requirements.txt`에 정리했습니다.

## 범위와 입력

- `inspect_iso.py`, `inspect_resources.py`, `catalog.py`: ISO9660/LICE/마스터 테이블 분석.
- `build_selected_27.py`, `update_help_and_lineups.py`, `localize_*.py`: 편성 선정·제외와 한글 표시 수정.
- `plan_balance_25.py`, `apply_balance_25.py`: 추가 25편성의 능력치·무장 조정.
- `story_content_25.py`, `story_*.py`, `apply_story_25.py`: 작성한 대사, 합류 일정, 시나리오와 네이티브 훅.
- `campaign_*.py`, `apply_campaign_tuning.py`: 보상·적 강화·공통 무장 조정.
- `validate_*.py`, `story_vm.py`: 구조와 실제 게임 루틴 검사.
- `option_release/build_options.py`: 검증된 원본·최종 ISO와 변경 기록을 이용한 12옵션 데이터 생성.
- `option_release/validate_options.py`: 옵션을 합성하여 시나리오/보급 및 보상/적 강화 독립 동작 검사.

대부분은 `work_ogg/analysis`, ISO, 변경 저널, 이전 단계의 JSON 등 로컬 입력이 필요합니다. 입력에는 게임에서 추출한 데이터·RAM 덤프가 포함될 수 있어 이 저장소에 넣지 않았습니다. 따라서 이 소스만으로 게임 변경 과정을 처음부터 재현할 수는 없습니다. 배포용 패처는 릴리즈의 BIN과 루트 `build.ps1`만으로 빌드할 수 있습니다.

도구의 상대 경로는 당시 `work_ogg`/`work_ogs` 형제를 기준으로 합니다. 일부 실험용·예전 단계용 빌더는 과거 ISO 이름이나 PCSX2 설치 경로를 사용합니다. 사용 전 입력·출력 경로, 원본 해시, 적용 전 상태 가정을 확인하고 현재 작업 경로에 맞게 수정하세요. 일반 사용자는 이 도구를 실행할 필요 없이 릴리즈의 패처를 사용하면 됩니다.

## 공식 베이스 검증

`work_ogg/upstream_base`에는 압축된 일본판 원본과 공식 xdelta를 ISO 복사본 없이 검증하는 도구가 있습니다. `decode_zip_vcdiff.py`는 xdelta의 무압축 recode를 읽어 RFC3284 기본 명령표로 디코딩하고 557개 구간 체크섬과 일본판 MD5를 확인합니다. `source_image.py`는 로컬 `official_base_delta.json`을 이용하는 읽기 전용 sparse overlay이며, `rebase_canonical.py`는 기존 확장 마스터의 문자열을 Strg/Sent ID로 이식합니다. 원본 ISO·공식 패치·게임 바이트를 담은 로컬 저널은 별도 입력입니다.

## 편성 보존 검사

`party_policy_25.py`는 독립 기체 그룹과 28화 기존 편성 복구 스크립트를 정의합니다. `apply_party_25.py`는 검증 결과·원본 해시를 확인하고 배타적으로 연 시험 ISO에 작은 변경 기록을 남겨 적용합니다. `validate_party_25.py`는 실제 저장 데이터 처리 루틴을 실행합니다. 수정 전의 린 그룹 참조는 메모리에서만 재구성하므로 적용 후에도 회귀 검사를 반복할 수 있습니다.

이 검사 역시 로컬의 ISO·합류 일정 JSON·실행 RAM·옵션 BIN·기존 변경 기록을 입력으로 사용합니다. 맵 유닛 조회를 부재 조건으로 대체하고 영구 저장 데이터의 VM 복원을 검사하므로 전편 플레이나 실제 메모리카드 검사를 대신하지 않습니다. 자세한 조건은 `docs/party-preservation-v20261106.3.md`에 있습니다.

[검증 범위와 대사](../docs/story-consistency-v20261106.4.md)를 참고하세요.

## 지원 장비·후반 정비

`support_overhaul_policy.py`는 원래 환장 무장 지급과 여섯 아군의 진행도별 독립 무장 9종을 정의합니다. 기존 진행도 기반 Unit 선택 훅을 재사용하여 새 실행 코드는 추가하지 않습니다. `prepare_support_overhaul.py`·`validate_support_overhaul.py`·`apply_support_overhaul.py`는 로컬 입력과 적용 전 상태를 사용하는 준비·검증·기록 도구입니다. 원래 무장·다른 기체·파일럿의 보존과 단계·개조·지급 상태를 검사합니다. 메뉴용 IM에는 무장 조회를 검사하고, 전투용 생성·저장 기록은 SHARED를 사용합니다.

기존 8옵션의 제거된 SP1 비트와 새 9옵션의 지원 장비 비트는 서로 다른 버전으로 구별합니다. 이전 프로필은 하위 일곱 기능만 옮기고 새 두 기능은 꺼짐으로 인식합니다. 로컬 변경 기록에는 전체 리소스의 미변경 여백도 포함되므로, 빌더는 이 범위를 관리 구간에 포함하여 이전 적용본을 정확히 인식합니다.

공통 무장 옵션은 과거 변경 기록의 절대 위치 대신 현재 WTbl의 무장 ID로 대상을 찾아 적용합니다. Unit·Weap 테이블이 확장되어 위치가 달라져도 다른 무장을 덮어쓰지 않도록 전체 무장표 비교와 실제 게임 조회를 교차 검사합니다.

## 국지전5편 시험판

`regional_five_content.py`는 모든 새 대사, `regional_five_policy.py`는 네이티브 출격·승패 가드·대사 묶음·스테이지 제목 구성입니다. `prepare_regional_five.py`는 빈 LICE 키2035~2039에 들어갈 작은 리소스를 준비하고 `apply_regional_five.py`는 단일 시험 ISO에 배타적으로 적용하며 역방향 해시를 확인합니다. 원작34화는 두 변형 모두 연결 장면과 분기를 갖고, 기존35·36화 스크립트와 최종전 종료 처리는 그대로입니다.

`audit_story_layout.loadarc`는 캐시의 위치만 이용하고 키·개수는 현재 파일에서 읽습니다. LICE13/14에5개씩 추가되고 기존 UNTD 상위 범위에서 빠져 있던6,144바이트도 보완합니다. 새 영구 플래그58,0은34화 연결 장면에 예약합니다. 새 전장 내부의 시작·통신·종료 플래그는 맵 로컬0,0~2입니다.

`validate_regional_five.py`는 제목·문자열·이력·이벤트 등록과 게임의 병력 수 비교·다음 화 처리 함수를 실행합니다. 병력 수는 시험에서 공급하며 화면상 배치·전투를 실행하지 않습니다.25인 육성 보존과 영구 Save/Diff 배열의7개 새 VM 복원도 점검합니다. 메모리카드 파일 I/O를 흉내 낸 검사가 아닙니다. 실제 PCSX2 테스트는 사용자가 진행합니다.

원래 화수와 표시 화수를 혼동하지 마세요. 기존 `CHAPTER_KEYS`와25인 후속 장면의35·36은 원래2033·2034를 뜻하며,12번ON일 때만 표시40·41입니다. 새35~39는2035~2039입니다. 추가25인 옵션은 새 전장 내 추가 인물 대사만 제어하고,12번은 진입·연결 장면·Stag 제목·화수를 제어합니다. 적 강화는 새 적160기의6/8단계를 독립 전환합니다.

`prepare_regional_density.py`는 최신 보스 적용 상태에서 각 추가 전장의 일반 적16기만 늘립니다. 기존28행(아군 선택12·일반 적14·보스2)은 그대로 두고 새16행은 좌표만 바꾸어 복제합니다. 일반 적30·보스2, 전체44행입니다. `apply_regional_density.py`는 작은 UNTD5개와 디렉터리 포인터5개만 바꾸고 전체 역방향 SHA-256으로 다른 바이트 보존을 확인합니다. 기존 본편 적 수·마스터·대사·초상화는 유지합니다.
