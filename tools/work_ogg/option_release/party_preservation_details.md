# 추가 편성 보존 수정 — v20261106.3

개선 순서의 2단계입니다. 추가 25편성에 대해 본편의 등장·이탈, 출격 제한, 부대 재편 처리가 보유 상태와 육성 기록에 미치는 영향을 점검했습니다.

## 확인한 문제와 수정

추가한 린의 휴케바인(키 `0x701`)이 원래 휴케바인과 동일한 기체 그룹 `0x4AF`를 물려받았습니다. 원래 기체 `0x4AD`의 보유 상태를 바꾸는 본편 명령은 그룹으로 대상을 찾으므로, 추가 기체가 먼저 저장된 경우 추가 휴케바인과 현재 탑승 파일럿까지 비활성화했습니다. 실제 게임 루틴에서 이 현상을 재현했습니다.

추가 휴케바인의 그룹 참조만 `-1`로 바꿔 독립 기체로 취급합니다. SHARED/IM 양쪽의 정비 전·후 레코드, 총 4곳에 적용했습니다. 다른 24편성의 기체 그룹과 추가 파일럿의 그룹 참조는 이미 독립 상태였습니다. 원래 기체의 이벤트, 능력치, 정신기, 개조·무장 설정은 바꾸지 않았습니다.

이전 버전에서 영향을 받은 세이브를 위해 28화 시작의 원래 기체 활성화 명령 뒤에 **기존 추가 기체만 활성화**하는 명령 1개를 넣었습니다. 경험치·PP·개조 상태를 초기화하거나 없는 기체를 새로 지급하지 않습니다. 현재 탑승 파일럿의 보유 상태도 복구합니다. 추가 시나리오를 켠 스크립트와 끈 스크립트에 모두 포함합니다. 이미 28화 시작 이벤트를 지난 세이브에서는 이벤트가 소급 실행되지 않습니다.

옵션을 껐을 때 사용하는 3화 보급 스크립트가 상위 MAP14 아카이브의 선언된 범위를 벗어나 있던 구조도 고쳤습니다. 3화 보급과 새 28화 복구 스크립트가 모두 그 범위 안에 들어갑니다. 실제 플레이 오류의 재현 없이 구조 검사로 확인한 항목입니다.

## 검증 방법과 범위

- 정비 전·후 상태를 포함한 진행도 3가지와 원래 기체의 보유 여부 2가지, 총 6가지 조건에서 수정 전의 동반 비활성화와 수정 후 보존을 확인했습니다.
- MAP14의 41개 스크립트 파일에서 편성 관련 명령을 추출해 실제 R5900 저장 데이터 처리 루틴으로 실행했습니다. 파일 수는 전체 화 수와 다릅니다. 상세 명령 수는 함께 제공한 검증 JSON을 참고하세요.
- 추가 25기·25명을 먼저 등록하고, 본편 명령이 대상으로 삼는 원래 기체 79종과 파일럿 77명을 함께 둔 통제된 조건입니다. 각 명령은 동일한 시작 저장 데이터에서 개별 실행했습니다.
- 각 추가 기체의 216바이트 기록과 파일럿의 92바이트 기록, 저장 슬롯과 보유 상태를 비교했습니다. 전체 편성에 적용되는 의도된 출격 제한 플래그는 허용하고, 경험치·PP·개조 등의 나머지 기록은 보존되는지 검사했습니다. 출격 제한을 무시하는 수정은 하지 않았습니다.
- 합류 가드 22개의 재실행 시 중복 지급이 없고, 추가 25명·25기가 등록되는지 확인했습니다. 기존 육성값을 둔 반복 검사도 통과했습니다.
- 8·19·31화 지점과 갈아타기 후, 총 4회 영구 저장 데이터를 새 VM에 복원했습니다. 갈아타기 관계와 합류 중복 방지 상태를 확인했습니다.
- 이전 버전의 비활성화 상태를 만든 뒤 새 데이터를 로드하여 28화 복구 명령을 실행했습니다. 기록 보존, 반복 시 추가 변화 없음, 미보유 시 지급 없음도 확인했습니다.
- 128가지 옵션 조합의 파일 범위·스크립트 포인터·양쪽 마스터의 독립 그룹과 복구 명령을 검사했습니다. 실제 시험 ISO의 128조합 전환 및 원복도 검증했습니다.

맵 유닛 조회는 유닛이 없는 조건으로 대체했습니다. 합류 그룹 명령은 직접 가로채되 실제 게임의 UNTD 등록 루틴을 실행했습니다. 재로드 검사는 영구 저장 데이터 배열을 새 VM에 복원하는 방식으로, 실제 메모리카드 I/O가 아닙니다. 맵 위 강제배치·경로 탐색 전체 동작이나 PCSX2 전편 실플레이를 완료한 검증은 아닙니다.

패치 후 게임을 완전히 새로 부팅하고 일반 세이브를 불러오세요. 예전 세이브 스테이트에는 수정 전 코드나 데이터가 남을 수 있습니다. 새 25편성 시나리오는 기존 안내대로 새 게임에서 시작합니다.
